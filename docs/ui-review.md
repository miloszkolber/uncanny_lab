## Initial focus and the skip link

A cross-engine keyboard audit found that the skip link was unreachable in the forward tab order even though it precedes the command trigger in the document. The cause was `route()`, which moved focus to the page heading on every call including the first render. Focus therefore started inside the main landmark before any interaction, and pressing Tab moved further into the page content, so the control that exists to bypass repeated page chrome could not be reached from the top of the document.

Focus now moves to the page heading only on an actual view change. `route()` takes an explicit flag and the initial render passes `false`; a hash change still focuses the new heading, which is the useful behavior for single-page navigation. The regression asserts both halves of that contract, and reverting the change fails it. Verified in the browser: on load the skip link is the first Tab stop, and activating it moves focus onto the main landmark.

## Known core gap and integration limits

In the unchanged frozen Command Palette, Chromium's native `input[type="search"]` consumes the first Escape when the query is nonempty: it clears the query while the dialog stays open. A second Escape closes and returns focus correctly. This differs from the component's documented one-Escape dismissal contract. The probe observed `open=true/query=unmatched-command`, then `open=true/query=""`, then `open=false/focus=command-trigger`. The shared-package owner received this evidence; the consumer does not edit frozen bytes, use private fields, or install a competing controller to conceal it. Empty-query Escape, Ctrl+K dismissal, command activation, and focus return remain available.
